## 2024-03-12 - Added Accessible Keypad Interactions
**Learning:** The `Keypad` component inside the transaction flow is visually customized without using native `<button>` styles directly. Since these buttons aren't standard labeled inputs, ARIA labels for symbol keys (like "DEL" and ".") must be manually mapped so screen readers read "Delete" or "Decimal point" instead of skipping or misinterpreting them. Furthermore, custom buttons lacking `focus-visible` states cause severe usability issues for keyboard navigation within the transaction flow. Adding explicit `focus-visible:ring-2 focus-visible:ring-primary` combined with active scaling feedback dramatically improves tactile response for fast keypad entry without disrupting the visual design.
**Action:** When implementing custom visual keypads or number entry surfaces, always explicitly map non-alphanumeric keys to human-readable `aria-label`s. Ensure standard touch/active scaling and keyboard focus styles (`touch-manipulation`, `active:scale-95`, `focus-visible`) are consistently applied.
